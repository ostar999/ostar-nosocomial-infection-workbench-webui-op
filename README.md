# 欧星星 · AI 院感工作台（独立 Web 版）

> 当前是 Web / Docker 版本，DeepSeek Harness 插件版本地址为：https://github.com/ostar999/ostar-dsh-nosocomial-infection-workbench-op

一个可独立部署的医院感染病例分析工作台。浏览器打开即可完成病例任务管理、材料导入、结构化事实抽取、院感判定与诊断分析、报告导出、病例时间线、病例问答和院感助手问答。

支持两种部署方式：

- **Node.js 本机启动**：`npm start` / `npm run dev`；
- **Docker 部署**：本地构建镜像，或直接拉取 Docker Hub 镜像。

本版本不依赖 DeepSeek Harness：模型由本应用直接连接 OpenAI 兼容接口，病例数据、模型设置和会话都保存在本机。

## 环境准备

### 必需

| 依赖       | 要求                             | 说明                                             |
| ---------- | -------------------------------- | ------------------------------------------------ |
| Node.js    | **22.13+（推荐 24/25）**         | `pdfjs-dist` 6.5 与内置 `fetch`/Web Streams 要求 |
| npm        | 随 Node.js 安装                  | 安装依赖、启动服务                               |
| 现代浏览器 | Chrome / Edge / Safari / Firefox | 支持 ES2020、CSS 变量、`color-mix`               |

### 可选本机工具

这些工具只在特定格式导入时使用；缺少时其他功能不受影响。

| 工具        | 用途                             | 安装示例                          |
| ----------- | -------------------------------- | --------------------------------- |
| `pdftotext` | 可选，PDF 版式更好的快速路径     | macOS：`brew install poppler`     |
| `mutool`    | 可选，`pdftotext` 不可用时的回退 | macOS：`brew install mupdf-tools` |

说明：

- PDF 文本层由内置 `pdfjs-dist` 解析，未安装 poppler/mutool 也能导入；
- 有 `pdftotext`/`mutool` 时优先使用，版式保留更好；
- `.docx/.xlsx` 由内置零依赖解析器直接读取；
- 旧版 `.doc/.xls` 解析不支持，导入会标记失败，请另存为 `.docx/.xlsx`；
- 扫描版 PDF 没有文本层时，当前版本不做 OCR，需要先自行 OCR 或转成可复制文本的 PDF；
- PDF 通过浏览器打印生成，不需要 LibreOffice。

### 检查环境

```bash
node -v
npm -v
```

可选检查：

```bash
command -v pdftotext
command -v mutool
```

## 启动

### 1. 进入目录

```bash
git clone https://github.com/ostar999/ostar-nosocomial-infection-workbench-webui-op.git
cd ostar-nosocomial-infection-workbench-webui-op
```

本地目录名可以自行修改，后续命令中的路径按实际目录替换。

### 2. 安装依赖

```bash
npm install
```

说明：前端 React 运行时已经放在 `public/vendor/`，正常启动不要求先执行 `npm install`；只有在重新安装或更新依赖时才需要。

> 升级只更新代码和依赖，**不要删除 `data/`**。病例、材料、设置和会话都保存在该目录。

### 3. 启动服务

```bash
npm start
```

默认地址：

```text
http://127.0.0.1:8787
```

终端会打印实际地址。开发时也可以直接用：

```bash
npm run dev
```

`npm start` 和 `npm run dev` 启动成功后会自动打开默认浏览器。

如果不需要自动打开，例如服务器、Docker 或 CI 环境：

```bash
IW_NO_OPEN=1 npm start
```

### 4. 指定端口和数据目录

```bash
PORT=9000 npm start
```

```bash
IW_DATA_DIR=/path/to/infection-data PORT=8787 npm start
```

### 5. 局域网访问

```bash
HOST=0.0.0.0 PORT=8787 npm start
```

默认只监听 `127.0.0.1`。改成 `0.0.0.0` 后同网段设备可访问，但应用没有内置多用户登录；公网或不可信网络必须自行加反向代理、认证和 HTTPS。

### 6. Docker 部署

本地构建：

```bash
docker compose -f docker/docker-compose.yaml up -d --build
```

直接使用 Docker Hub 镜像：

```bash
docker compose -f docker/docker-compose.hub.yaml up -d
```

Docker Hub 镜像：

```text
ostar999/ostar-nosocomial-infection-workbench-webui:latest
```

支持：

- `linux/amd64`（x86_64）；
- `linux/arm64`（ARM64）；
- Docker 命名卷或宿主机目录持久化 `data/`；
- 容器内关闭自动打开浏览器；
- 健康检查和非 root 用户运行。

本地构建版使用 Docker 命名卷，远程版使用 `docker/data/` 宿主机目录；两种方式使用同一个容器名和端口，不要同时启动。详细说明、切换方式、数据迁移和备份方式见 [docker/README.md](docker/README.md)。

2. 填写 API Key；
3. 填写 API Base URL；
4. 选择 API 协议；

## 详细功能

### 1. 病例任务

- 新建病例任务，任务名称必填（红色星号标记），可填写患者姓名、年龄、性别、分组和备注；
- 左侧任务列表按分组显示；
- 支持搜索任务、按创建时间/更新时间/名称排序；
- 支持重命名、修改分组、删除；
- 任务状态分为未分析、分析中、已完成、失败；
- 支持批量导入病例、批量分析、批量删除；
- 批量分析可设置最高并行数，侧栏显示并行数、进度、活动任务和取消入口；
- 任务卡片显示材料数量、分析状态和最近更新时间。

### 2. 材料导入与解析

支持单个病例的材料区：

- 拖拽单个文件；
- 拖拽整个病例文件夹；
- 浏览器文件选择上传；
- 点击「导入文件夹」，通过浏览器目录选择器选择本机文件夹并上传；
- 材料导入不再提供服务器路径输入，材料只能由浏览器上传或拖拽。

支持格式：

| 格式            | 解析方式                                           |
| --------------- | -------------------------------------------------- |
| `.docx`         | 读取 OOXML，保留段落、表格、换行                   |
| `.xlsx`         | 读取共享字符串、多工作表、日期格式                 |
| `.pdf`          | 内置 `pdfjs-dist`；有 poppler/mutool 时优先使用    |
| `.csv`          | 自动识别分隔符和 UTF-8/UTF-16/GB18030 编码         |
| `.md` / `.txt`  | 直接读取文本                                       |
| `.doc` / `.xls` | 不支持，导入会标记解析失败，请另存为 `.docx/.xlsx` |

> **不支持扫描件或图片型 PDF**：这类 PDF 没有文本层，导入时会直接报错提醒，不做 OCR。请上传可复制文字的 PDF，或改用 Word/文本文件。

材料区会显示：

- 文件名、格式、字符数；
- 解析成功/失败状态；
- 失败原因；
- 查看材料内容；
- 下载材料；
- 删除材料。

失败材料不会阻断其他材料和后续分析，但报告会提示材料缺失。

### 3. 综合分析

流程分为三个阶段：

1. **材料整备**：汇总病例材料，按当前模型的上下文窗口分配预算；
2. **结构化事实抽取**：提取患者、入院时间、器械时段、培养/检验、抗菌药物、感染事件、时间线等结构化事实；
3. **判定与报告**：按内置 skill 的规则表逐条判定，生成《医院感染分析报告》。

内置规则包括：

- `rules/stage1_general.json`：通用判定；
- `rules/stage3_special.json`：专项判定；
- `rules/checklists.json`：检查清单；
- `rules/scoring.json`：评分与可能性；
- 857/861/862/863/509 解读、2013/2018/2025 指南解读、2001 标准、187/136 号、潜伏期表等参考材料。

报告内容：

- 病例概况；
- 医院感染判定结论；
- 临床诊断与专项诊断；
- 判定/排除依据；
- 可能性评估与区间；
- 信息缺口与建议；
- 声明。

分析时可以选择「特别关注」问题，限定本次分析重点。

如果材料列表中存在解析失败或不支持格式的文件，点击开始分析前会弹出确认，列出失败文件；确认后才继续分析，避免在信息缺失时静默分析。

### 4. 分析概览与进度

运行中显示：

- 当前阶段：材料整备 / 结构化事实抽取 / 判定与报告 / 文件生成；
- 已运行时间；
- 阶段完成状态；
- 抽取阶段已输出字符数；
- 模型思考字数；
- 动态不确定进度条；
- 取消分析按钮；
- 错误信息与重试入口。

分析完成后显示：

- 当前模型；
- 报告字符数；
- 用时；
- token 用量；
- 警告和缺失材料提示。

### 5. 报告与导出

每份分析会在任务目录生成：

```text
院感分析报告.md
院感分析报告.html
院感分析报告.txt
院感分析报告.docx
分析明细.json
```

支持：

- 面板内预览 Markdown / HTML；
- 复制报告；
- 导出 Markdown；
- 导出 HTML（可打印、自带样式）；
- 导出 TXT；
- 导出 Word（`.docx`）；
- 「打印 / 另存为 PDF」：打开 HTML 报告并调用浏览器打印，不依赖 LibreOffice；
- 一次选择多种格式。

报告正文使用标准官方名称，不出现内部目录、`.md` 路径和反引号；表格优先，结论先行。

### 6. 病例时间线

根据分析明细中的结构化事实生成：

- 入院、转科、手术、器械置入/拔除、培养、感染事件；
- 有创通气、导尿管、中心静脉导管时段；
- VAP/CAUTI/CLABSI 48 小时窗口；
- SSI 30 天/90 天窗口；
- 14 天重复感染窗；
- 窗内、未到起点、超出终点标记。

### 7. 病例问答

围绕当前病例追问，上下文包括：

- 材料原文；
- 结构化分析明细；
- 已生成报告；
- 更早对话摘要；
- 最近 10 条问答；
- 必要时加载相关标准规则。

能力：

- 多轮问答；
- 引用标准条款；
- 回答中给出条文号；
- 支持 Markdown/HTML/TXT/Word 导出，并可用浏览器打印为 PDF；
- 清空当前对话；
- 运行中取消；
- 底部状态栏显示轮次、token/s、用量、缓存命中、上下文占比。

### 8. 院感助手

独立通用知识问答：

- 不读取病例材料；
- 支持多会话；
- 新建、重命名、删除、批量删除；
- 搜索会话；
- 按更新时间/创建时间排序；
- 建议问题；
- Markdown/HTML/TXT/Word 导出，并可用浏览器打印为 PDF；
- 引用追溯；
- 与病例问答共享上下文压缩和状态栏。

适用：

- 标准条文解释；
- VAP/CAUTI/CLABSI/SSI 概念区别；
- 诊断思路；
- 防控措施；
- 报告写作。

不适用：

- 具体病例分析（请使用病例分析）；
- 替代临床诊断。

### 9. 上下文管理

- 按当前模型 `contextWindow` 分配输入预算；
- 材料、标准、摘要、最近对话分别计入预算；
- 超过最近 10 条消息后，较早对话由模型压缩为持久摘要；
- 后续请求只发送摘要 + 最近 10 条消息；
- 界面中的历史消息不会删除；
- 摘要、压缩次数、上下文统计保存在任务/会话数据中；
- 刷新页面或重启服务后仍可恢复；
- 底部状态栏显示上下文百分比、已用 token、剩余 token；
- 点击圆环展开分段明细：系统提示、材料、分析明细、报告、摘要、最近对话、联网结果、本次问题；
- token 为保守估算（中文约 1 字 ≈ 1 token），不是供应商精确 tokenizer。

### 10. 模型接入设置

支持多家 OpenAI 兼容供应商。

#### 供应商

- 显示名称；
- API Base URL；
- API 协议：
  - **OpenAI Chat Completions**：`/chat/completions`
  - **OpenAI Responses**：`/responses`
- API Key；
- 启用/停用；
- 删除供应商；
- 设为当前供应商；
- 获取模型列表；
- 若 `/models` 返回 `context_length`、`max_completion_tokens`、`input_modalities` 等能力字段，添加模型时会自动带入上下文、最大输出和输入类型；
- 检测连接。

#### 模型

每个模型独立配置：

- 显示名称；
- 模型 ID；
- 最大输出 / Max output tokens；
- 上下文 / Context window；
- 输入类型：文本 / 图片；
- 推理等级开关；
- 思考强度档位：`minimal` / `low` / `medium` / `high` / `xhigh` / `max`；
- 每档对应的 API 参数值；
- 默认强度；
- 设为默认模型；
- 单独检测该模型；
- 删除模型。

默认值：

| 模型类型      | 最大输出 | 上下文 |
| ------------- | -------- | ------ |
| DeepSeek 模型 | 384K     | 1M     |
| 第三方模型    | 128K     | 256K   |

默认勾选思考强度：

```text
low / medium / high / max
```

`minimal`、`xhigh` 作为可选项，按模型支持情况勾选。

#### 协议说明

- Chat Completions 兼容性最好；
- Responses 适合明确支持 `/responses` 的供应商；
- 如果供应商返回协议错误、404 或流解析失败，切回 Chat Completions；
- 拉取模型列表成功只代表列表接口可用，不代表当前账号有该模型的推理权限；
- 火山引擎等平台可能要求使用推理接入点 ID（`ep-...`），而不是模型名称。

#### 密钥安全

- API Key 只存在 `data/settings.json`；
- 浏览器端读取时返回空字符串和 `hasApiKey`；
- 设置文件权限 `600`；
- 不要把 `data/` 提交到 git 或打包分发。

### 11. 外观与主题

- 深色 / 浅色 / 跟随系统；
- 7 种主题色：青、蓝、青绿、绿、紫、橙、玫红；
- 主题入口在顶部太阳图标；
- 设置保存在浏览器 `localStorage`；
- 首屏提前应用主题，减少闪烁；
- 浅色模式覆盖主界面、模型设置、弹层、运行栏、上下文明细、分析进度等。

### 12. 批量操作

- 批量导入：拖入或选择浏览器本机的上级目录，每个子文件夹视为一个病例；
- 批量分析：多选任务，按最高并行数执行，默认 4，可调 1–16；
- 批量分析侧栏显示并行数、完成数、活动任务和取消；
- 批量删除：独立入口，二次确认；
- 批量分析使用当前模型配置，任务之间互不串用上下文。

```text
院感分析报告.txt
```

```bash
tar -czf infection-workbench-backup.tar.gz data/
```

| ------------- | ----------- | ---------------------------------- |
| `PORT`        | `8787`      | HTTP 端口                          |
| `HOST`        | `127.0.0.1` | 监听地址；`0.0.0.0` 允许局域网访问 |
| `IW_DATA_DIR` | `./data`    | 数据目录                           |
| `IW_NO_OPEN`  | 未设置      | 设为 `1` 时启动后不自动打开浏览器  |

示例：

```bash
HOST=127.0.0.1 PORT=8787 IW_DATA_DIR=./data npm start
```

## 常见问题

### 页面打开显示「未配置模型」

进入模型设置填写 API Key、API 地址和至少一个模型，保存后重载。

### 获取模型列表成功，但检测失败

常见原因：

1. 默认模型不是当前列表中的模型；
2. 账号没有该模型的推理权限；
3. 模型名称需要换成推理接入点 ID（`ep-...`）；
4. API 协议选错；
5. 接口地址不完整或多了路径。

每个模型行有独立的「测」按钮，状态会显示实际请求的模型名。

### PDF 导入失败

PDF 文本层由内置 `pdfjs-dist` 解析，通常不需要额外安装。

如果仍失败，点击顶部「环境检查与依赖」确认 PDF.js 是否就绪；poppler/mutool 是可选增强，不是必需依赖。

如果 PDF.js 成功读取但没有文本层，说明该 PDF 是扫描件或图片型 PDF。当前版本不支持这类文件，也不做 OCR；请先 OCR，或改用可复制文字的 PDF / Word / 文本文件。

### 如何导出 PDF

在报告、病例问答或院感助手的导出对话框中点击「打印 / 另存为 PDF」：

1. 报告在隐藏 iframe 中加载，不会打开新标签页；
2. 浏览器打开原生打印窗口；
3. 在打印目标中选择「另存为 PDF」；
4. 保存文件。

不需要安装 LibreOffice。PDF 由浏览器打印引擎生成，分页可能与 Word 版略有差异。

### 局域网打不开

确认使用：

```bash
HOST=0.0.0.0 PORT=8787 npm start
```

并检查系统防火墙是否放行端口。

### 端口被占用

```bash
PORT=9000 npm start
```

### 刷新后上下文还在，但历史消息没有删除

这是预期行为：压缩只改变发给模型的内容，不删除界面中的历史消息。

### 分析很慢

耗时取决于：

- 材料长度；
- 模型速度；
- 输出上限；
- 思考强度；
- 是否触发上下文压缩；
- Word 报告生成。

### 回答或报告被截断

提高当前模型的最大输出，或降低思考强度。报告和抽取共用模型输出预算。

## 已知限制

- 无内置多用户登录；
- 无内置联网搜索；需要原文时使用引用卡中的官方链接或自行检索；
- 扫描 PDF 不做 OCR；
- 旧版 `.doc/.xls` 解析不支持，需另存为 `.docx/.xlsx`；
- token 是估算值，不保证与供应商计费完全一致；
- 不同供应商对 reasoning 内容、Responses 协议、`reasoning_effort` 的支持程度不同；
- 报告是辅助分析，不构成临床诊断。
